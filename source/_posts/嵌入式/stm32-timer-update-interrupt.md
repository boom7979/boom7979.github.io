上节已经知道 PSC、ARR 如何决定定时器周期。本节进一步理解 CNT 如何运行、更新事件与真正的 CPU 中断有何区别，以及 UIF、UIE、CEN 在其中分别起什么作用。内容来自本对话的理论讲解，**未包含开发板实测**。

## 核心概念

| 名称 | 所在位置 | 功能 |
| --- | --- | --- |
| PSC | `TIMx_PSC` | 分频，决定 CNT 更新的速度 |
| ARR | `TIMx_ARR` | 一轮计数的自动重装载上限 |
| CNT | `TIMx_CNT` | 当前计数值 |
| CEN | `TIMx_CR1` | 计数器使能位 |
| UIF | `TIMx_SR` | 更新中断标志位（Update Interrupt Flag） |
| UIE | `TIMx_DIER` | 更新中断使能位（Update Interrupt Enable） |
| UG | `TIMx_EGR` | 软件生成更新事件的控制位 |

记忆法：**CEN 决定数不数，UIF 记录有没有更新，UIE 决定是否请求更新中断。**

## 工作原理

以 TIM2 输入时钟 1000 Hz、`PSC=9`、`ARR=4` 为例：

- PSC 分频后，CNT 频率为 $1000/10=100$ Hz，即 **每 0.01 秒推进一个计数节拍**。
- CNT 的一个周期为 `0 → 1 → 2 → 3 → 4 → 0`。
- 每轮包含 5 个节拍，周期 $5/100=0.05$ 秒。

```text
TIM 时钟 → PSC 分频 → CNT 循环计数 → 更新事件（UEV）
                                            ↓
                                    设置 UIF（通常情形）
                                            ↓
                          UIE 允许且 NVIC 已配置/使能
                                            ↓
                                  CPU 进入 IRQHandler
                                            ↓
                              处理任务并清除待处理标志
```

**更新事件不等于 CPU 立即执行中断。** 例如 `CEN=1、UIE=0` 时，计数器仍可运转并产生更新事件，但不会因为更新事件向 NVIC 发出更新中断请求。

### 用标准外设库理解中断服务函数

下面是课程中的**示意代码**，不是本次编译运行结果：

```c
void TIM2_IRQHandler(void)
{
    if (TIM_GetITStatus(TIM2, TIM_IT_Update) == SET)
    {
        // 这里执行周期性任务
        TIM_ClearITPendingBit(TIM2, TIM_IT_Update);
    }
}
```

硬件 CNT 不依赖 CPU 手动执行 `CNT++`。中断函数是对更新请求做出响应，而不是负责让 CNT 重新计数。

`TIMx_EGR.UG` 可以生成软件更新事件，用于使部分预装载参数生效。初始化时它也可能导致 UIF 被置位；如随后要开启中断，应根据具体寄存器设置清理待处理状态。更新事件及标志的细节受 URS、UDIS 等配置影响，不能一概而论。

## 示例：中断函数需要 0.2 秒

假设 TIM2 每 1 秒产生更新事件，CPU 每次处理约 0.2 秒，并且能够及时开始响应：

| 时间点 | 定时器 | CPU |
| --- | --- | --- |
| 0 秒 | 第一次更新事件 | 开始执行中断函数 |
| 0.2 秒 | 仍在正常计数 | 中断函数结束 |
| 1 秒 | 第二次更新事件 | 再次响应中断 |
| 2 秒 | 第三次更新事件 | 再次响应中断 |

**我的回答（本对话记录）：** 下一次事件是在上一次中断开始后的约 1 秒发生，而不是中断执行结束后再数 1 秒。这个结论是针对**硬件更新事件**；CPU 实际进入中断服务函数的时刻还可能受到其他更高优先级中断或屏蔽影响。

## 易混点与自检

- **UIF 是标志，不是可无限存储事件次数的队列。** ISR 处理过慢时，多个更新事件可能合并为一个待处理状态。
- **UIE 不控制 CNT 是否计数**，不要和 CEN 混淆。
- **CNT 重装与 CPU 退出 ISR 不是同一个动作**，不存在“中断函数执行完才重新计时”的必然关系。
- **PSC、ARR 的生效时机**可能与预装载、更新事件有关，修改寄存器后不一定立即影响当前周期。
