这篇笔记记录了一次使用 DiskGenius 将系统盘 C 的 40GB 容量转移至 D 盘的实际操作。重点是理解分区位置对扩容的影响、BitLocker「暂停保护」与「完全解密」的区别，以及如何在调整后确认文件系统和 Windows 恢复环境正常。

## 一、环境与原始分区布局

**本次实测环境：**

- 分区工具：DiskGenius V5.4.6.1441 x64 免费版（操作完成后的界面显示为单文件 PE 版）。
- 系统：Windows，`manage-bde` 工具显示版本 `10.0.26100`；具体 Windows 版本名称未单独核实。
- 磁盘 0：Intel SSDPEKNU512GZ，NVMe SSD，实际显示容量约 476.9GB。
- 磁盘 1：Colorful CN600 1TB PLUS，实际显示容量约 931.5GB，作为 E 盘使用。

磁盘 0 的实际顺序为：

```text
磁盘 0（Intel NVMe SSD）
EFI 100MB → MSR 16MB → C: 278.75GB → 隐藏分区 988MB → D: 196.23GB

磁盘 1（独立 SSD）
E: 931.51GB
```

其中，C 与 D 虽然在同一块物理硬盘上，但中间隔着一个 988MB 隐藏分区。它在调整后仍被保留，Windows RE 后续也能识别其位置；因此，不能把它简单当成可以随意删除的多余空间。

**目标：** 将 C 盘容量减少 40GB，并将这 40GB 增加给 D 盘，尽量不影响原有数据、启动分区和恢复分区。

| 分区 | 调整前 | 调整后（实测显示） |
| --- | ---: | ---: |
| C 盘 | 278.75GB | 约 238.8GB |
| D 盘 | 196.23GB | 约 236.2GB |
| 隐藏分区 | 988MB | 988MB，保留 |
| EFI / MSR | 100MB / 16MB | 不变 |

> **注意：** 分区操作属于高风险的磁盘元数据与数据移动操作。开始前应先备份 C、D 盘的重要文件，并保证供电稳定。本次对话没有提供备份完成的独立验证记录，因此不能把「已备份」列为实测结论。

## 二、准备工作：检查 BitLocker 状态

最初在 DiskGenius 中，C、D、E 都显示为 BitLocker 加密分区。Windows「设备加密」页面只有「备份恢复密钥」，未显示「关闭 BitLocker」选项；随后通过 Windows 设置关闭了设备加密。

使用管理员 PowerShell 查询各卷：

```powershell
# 查询指定分区
manage-bde -status C:
manage-bde -status D:
manage-bde -status E:

# 也可以一次查看所有 BitLocker 卷
manage-bde -status
```

**实际观察：** C、D 曾显示「解密进行中」，最终两盘均显示：

```text
转换状态:       完全解密
已加密百分比:   0.0%
BitLocker 版本: 无
加密方法:       无
保护状态:       保护关闭
```

这比仅看到「保护关闭」更有判断价值：**保护关闭不等于已经完成解密**。

当 Windows 设置页面仍显示「正在解密」时，进一步检查 E 盘，发现：

```text
卷 E: [新加卷]
大小:           931.51 GB
转换状态:       解密进行中
已加密百分比:   47.3%
保护状态:       保护关闭
锁定状态:       已解锁
```

因此，**本次已确认 C、D 完全解密，E 当时仍在解密**。Windows 设置中的整体进度提示不能代替逐卷检查。

### 需要区分的三个操作

| 操作 | 作用 | 是否把数据还原为明文 |
| --- | --- | --- |
| 暂停 BitLocker 保护 | 暂时不执行常规保护校验，便于某些系统维护操作 | 否 |
| 暂停正在进行的加密/解密 | 停在当前转换进度，稍后继续 | 否 |
| 关闭 BitLocker 并解密 | 将加密卷转换为未加密状态 | 是，完成后为明文 |

例如，下面的命令是**暂停 E 盘的解密过程**，不是「暂停 BitLocker 保护」：

```powershell
# 暂停 E 盘正在进行的解密
manage-bde -pause E:

# 查看 E 盘是否已暂停
manage-bde -status E:

# 之后恢复转换进度
manage-bde -resume E:
```

对话中计划暂停 E 盘解密，但没有提供暂停后的命令输出，因此其最终暂停状态**待确认**。E 盘位于另一块物理硬盘，不参与此次 C/D 分区调整。

### 本次为什么进行了完整解密？

这是当时为了降低分区工具处理加密卷时的兼容性不确定性而采用的保守方案，**不是所有磁盘维护都必须完整解密**。

BitLocker 的「暂停保护」通常很快；但暂停保护后数据仍处于加密状态。对于本次涉及 **缩小 C 盘、移动隐藏分区、扩展 D 盘** 的操作，是否能够仅暂停保护并完成无损调整，取决于具体工具版本、加密状态和操作方式。本次没有对「仅暂停保护」方案进行测试，因此不能断言 DiskGenius 5.4.6.1441 一定支持或一定不支持。

更合理的准备顺序是：**先备份恢复密钥和重要文件 → 核实当前分区工具对 BitLocker 调整的支持 → 再决定暂停保护还是完全解密**。完整解密往往耗时较长，重新加密也可能再次花费较长时间。

## 三、DiskGenius 实际扩容步骤

### 1. 选择 C 盘并调整容量

在 DiskGenius 中选中磁盘 0 的 C 盘，打开「调整分区大小 / 调整分区容量」窗口。本次实际设置如下：

```text
原 C 盘容量：       278.75GB
调整后的容量：     238.75GB
分区前部的空间：   0KB
分区后部的空间：   40.00GB
后部空间处理方式： 合并到 新加卷(D:)
```

关键在于**选择「合并到新加卷(D:)」**，而不是只留下 40GB 未分配空间。软件会根据当前分区布局安排后续移动与扩展操作。

### 2. 确认操作清单

点击「开始」后，DiskGenius 弹出了正式执行前的确认框，实际列出四个步骤：

```text
1. 检查各分区是否有错误
2. 调整 本地磁盘(C:) 的容量
3. 向前移动 分区(3)
4. 扩展 新加卷(D:) 的容量
```

这份清单十分重要：第 3 步是**移动 C、D 之间的 988MB 隐藏分区**，而不是将其删除。移动之后，D 盘才能利用新腾出的 40GB 空间。

正式执行前，应确认目标盘符、容量、移动对象和操作顺序，并检查数据备份情况。点击最终确认后，分区工具可能切换到预启动或 PE 环境；不要强制关机、断电或中途停止分区移动。

### 3. 操作后的分区情况

DiskGenius 完成后显示：

```text
EFI 100MB → MSR 16MB → C: 238.8GB → 隐藏分区 988MB → D: 236.2GB
```

**实测结论：** 40GB 已按计划从 C 盘划给 D 盘；隐藏分区、EFI 和 MSR 分区仍存在，未出现额外未分配空间。E 盘没有参与磁盘 0 的分区调整。

## 四、调整完成后的验证

完成分区操作后，已经能够返回 Windows 并在管理员 PowerShell 中运行检查命令。

### 1. 检查 C、D 盘文件系统

```powershell
chkdsk C: /scan
chkdsk D: /scan
```

两个盘的实际输出均包含：

```text
Windows 已扫描文件系统并且没有发现问题。
无需采取进一步操作。
```

| 项目 | C 盘 | D 盘 |
| --- | ---: | ---: |
| CHKDSK 检查结果 | 未发现问题 | 未发现问题 |
| 报告的坏扇区 | 0KB | 0KB |
| CHKDSK 报告的可用空间 | 63,086,388KB | 139,647,932KB |

这里的「坏扇区 0KB」是该次文件系统检查的输出，**不等于做过整盘物理坏块扫描，也不能据此保证所有文件内容都毫无变化**。

### 2. 检查 Windows 恢复环境

```powershell
reagentc /info
```

本次实际输出的关键部分：

```text
Windows RE 状态: Enabled
Windows RE 位置: \\?\GLOBALROOT\device\harddisk0\partition4\Recovery\WindowsRE
REAGENTC.EXE: 操作成功。
```

这说明 Windows 恢复环境已启用，且配置仍指向磁盘 0 的第 4 个分区，与保留下来的恢复分区位置一致。**本次未实际进入 Windows RE 做启动测试**，因此不能把「恢复环境已成功启动」写成实测结论。

综合 Windows 正常进入、C/D 文件系统检查通过、恢复环境配置正常三项结果，可以判断本次分区扩容**基本成功，未发现明显异常**。

## 五、踩坑与经验总结

1. **「同一硬盘」不等于「相邻分区」。** C 与 D 中间隔着恢复分区，扩容时需要安排额外的分区移动步骤。
2. **不要把隐藏分区当作垃圾分区。** 本次保留了 988MB 分区，`reagentc /info` 仍能识别 Windows RE。
3. **「保护关闭」不代表「完全解密」。** 需要同时查看「转换状态」和「已加密百分比」。
4. **设备加密页面的总进度可能对应其他卷。** 本次 C/D 完全解密后，E 仍在解密，导致界面继续显示「正在解密」。
5. **暂停解密和暂停 BitLocker 保护是两回事。** `manage-bde -pause E:` 暂停的是转换任务，不能理解为已恢复 E 盘的数据保护。
6. **完整解密是一种兼容性优先的选择，不是通用硬性要求。** 以后应先确认工具能力，避免无谓地经历解密及重新加密的长时间等待。
7. **扩容后不能只看容量变化。** 还应核对 Windows 启动、文件系统及恢复环境；若涉及重要数据，最好抽查实际文件能否打开。
